أخطاء وُجدت وأُصلحت في هذه الجلسة

عدم إعادة توليد القنب/التوت (hemp / berry_bush) كانا يُحصَدان بلا رجوع أبدًا رغم أن respawnObject() يدعمهما بالكامل — كانا فقط مفقودَين من قائمة الأنواع المسموح لها بإعادة الجدولة. أُصلح في game.js، ونُقل السلوك الصحيح مباشرةً إلى Unity (ResourceRespawnService.cs).
حد "12 stack" لصندوق التخزين لم يكن مُطبَّقًا فعليًا موجود كنص وصفي فقط. أُضيف maxSlots إلى StorageInventory نفسه (وإلى InventorySystem.cs في Unity)، بحيث يُفرض على مستوى البيانات لا الواجهة فقط.
نظام الصياغة كان معزولًا فعليًا عن الإنتاج js/crafting/recipes.js (المُختبر بـ 30+ اختبار) لم يكن مُستوردًا في game.js إطلاقًا — الصياغة الحية كانت تقرأ من ITEMS_DATA[id].recipe بأرقام مختلفة تمامًا. تم توسيع recipes.js ليطابق الأرقام الرسمية (18 وصفة) وربطه فعليًا بـ game.js.
بيانات ميتة محذوفة عنصر door المكرَّر (نسخة طبق الأصل من wooden_door)، BUILDING_TIERS.door غير المُستخدَم إطلاقًا، واستيرادات JS ميتة (NODE_TYPES, keyboardProvider, touchProvider, Actions).
تصحيح توثيقي: نصف قطر Tool Cupboard BUILDING_SYSTEM.md كان يذكر 20 وحدة؛ الكود الفعلي (CONFIG.TC_RADIUS) يستخدم 25. صُحِّح في التوثيق ونُقل الرقم الصحيح إلى Unity.

ديون تقنية متبقية (لم تُعالَج بعد، للعلم فقط)

عنصر codelock معرَّف بلا أي منطق قفل فعلي موجود في سجل العناصر ويظهر في قائمة الصياغة، لكن لا يوجد أي كود يربطه بباب فعليًا — الأبواب تُفتح/تُغلق بـ E فقط بلا حماية.
inputSys/gamepadProvider غير مكتمل الربط يُنشأ نظام Input System كامل ويُضاف له مزوّد gamepad، لكن لا يوجد أي استدعاء فعلي لقراءة مدخلاته في حلقة اللعب — الحركة الفعلية تمر عبر مسارات إدخال أخرى (كيبورد/لمس مباشرة).
js/game.js لا يزال ملفًا أحاديًا ضخمًا (2797 سطر) لم يُفكَّك تدريجيًا إلى وحدات كما توصي PRD — هذا هو بالضبط سبب اختيار إعادة البناء الكامل في Unity بدل محاولة "تفكيكه" أكثر.

حالة أساس Unity

9 من أصل 15 نظامًا في الخطة الأصلية لها الآن كود C# فعلي (أساسي، غير مُختبر بمُصرِّف حقيقي): Core، طبقة البيانات، Inventory، Crafting، Survival، Player، Interaction، Building، Save. الباقي (World/Time-Weather، UI، Input Actions asset، Mobile Controls، Testing، Combat) لم يبدأ.

تنويه لا بد من تكراره: كل كود Unity كُتب في بيئة سحابية بلا Unity Editor مثبَّت. لم يُفتح، لم يُصرَّف، ولم يُشغَّل فعليًا بعد. تحقّقت فقط من توازن الأقواس في كل ملف، وصحة كل JSON، وتطابق كل المعرّفات المرجعية بين الملفات (صفر مرجع معلّق) — لكن هذا ليس بديلًا عن مُصرِّف C# حقيقي.

4. خارطة الطريق القادمة

الأساس (طبقة البيانات + الأنظمة الجوهرية) مبني. المراحل التالية تحوّله من "كود مجمَّع" إلى "لعبة قابلة للتشغيل فعليًا".

A

أول فتح فعلي + إصلاح أخطاء Compile

فتح unity/RustgameUnity/ في Unity Editor، تشغيل Rustgame → Import Seed Data، إصلاح أي خطأ compile يظهر (متوقّع بنسبة معقولة لأن الكود لم يُصرَّف من قبل).

معيار القبول: المشروع يُفتح بلا أخطاء Console حمراء، و~70 asset بيانات تُنشأ بنجاح.
B

مشهد أولي + Player Prefab + دمج الأنظمة

مشهد World.unity بسيط (أرضية + إضاءة)، Player Prefab يجمع CharacterController+PlayerController+SurvivalStats+InteractionController، وربط GameManager بكل شيء فعليًا (CollectSaveData الحالية placeholder فقط).

معيار القبول: يمكن الحركة والقفز والجري داخل Play Mode، وHunger/Stamina تنخفض حيًا.
C

Input Actions Asset + HUD أساسي

Action Maps (Desktop + Touch) عبر Input System Package، وCanvas UGUI بأشرطة Health/Hunger/Thirst/Stamina/Temperature + حزام 1-6.

معيار القبول: كل مدخل (WASD/Space/Shift/E) يعمل عبر Input Actions لا Input.GetKey مباشرة، والـ HUD يتحدّث حيًا.
D

BuildingPlacer/Ghost + عالم بسيط

وضع بناء فعلي (شبح شفاف + snap-to-grid + فحص تصادم)، وتوليد عدد من ResourceNode في مشهد اختباري بدل placeholder واحد.

معيار القبول: وضع جدار Twig وترقيته إلى Wood يعمل من البداية للنهاية.
E

اختبارات + أداء موبايل + Android Build

EditMode tests لـ CraftingSystem/InventorySystem/SurvivalStats (توازي tests/phase1.test.mjs)، وضبط IL2CPP+ARM64، وبناء APK أول تجريبي.

معيار القبول: كل الاختبارات خضراء، وAPK يُثبَّت ويعمل على جهاز حقيقي.
F

Combat / NPCs (Phase 2)

استخدام نموذج NPC الأصلي في game.js (ذئب/دب/عالِم) كمرجع سلوكي، لكن مع NavMesh حقيقي بدل الحركة الخطية المباشرة.

معيار القبول: مواجهة ذئب قابلة للربح بالأدوات الحجرية (نفس معيار PRD الأصلي).

6. خطوات التشغيل العملية

  1. تأكد من وجود unity/ محليًا: git pull origin main.
  2. افتح Unity Hub → Add → اختر rust-game/unity/RustgameUnity/.
  3. ثبّت/استخدم Unity 6000.0.35f1 (أو أي 6000.0 LTS متوفر لديك).
  4. انتظر أول فتح (بطيء — يبني Library/ من الصفر، وهنا تظهر أخطاء Compile إن وُجدت).
  5. من القائمة العلوية: Rustgame → Import Seed Data — ينشئ ~70 asset بيانات تلقائيًا.
  6. أرسل أي رسالة خطأ من نافذة Console بالضبط (نص أو لقطة شاشة) — تُصلَح هنا في الكود وتُرفع، وتكرر نفس الخطوات.
